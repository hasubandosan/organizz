# Категории, теги и связи между модулями (единые правила для всех модулей)

**Принцип: один источник правды. Модуль никогда не заводит «свои» теги/категории и не копирует
записи другого модуля — он хранит id и ссылки.**

## Категории и теги: два слоя
**Категория** = ЧТО это (тип покупки, элемент образа, приём пищи). **Тег** = признак (цвет, материал, срочность).
Физически это одно и то же: теги, хранятся в `tagIds`; различие — поле `kind: 'category' | 'tag'`.
**Зон в общем каталоге нет:** зоны (структура/дерево) каждый пользователь делает под себя внутри модуля.
1. **Системные** (встроенные, одинаковы у всех, только чтение): `backend/src/shared/systemTags.ts`,
   отдаются `GET /shared/system-tags`. id вида `sys:cp-wig`, вечные. Поле `scope` — в каких модулях
   виден (`['all']` или список слагов), `group` — группа для выпадашки, `kind` — `'category'` или `'tag'`.
   Правит каталог только владелец/архитектор.
2. **Личные** (у каждого пользователя свои, видны только ему): коллекция `tags`
   в модуле `shared` (поле `kind`, по умолчанию `'tag'`). Необязательное поле `scope` (массив слагов или `['all']`, по умолчанию везде).

## API (frontend/core/db.js)
```js
const opts  = await DB.getTagOptions('cosplays');                // категории + теги (системные и личные), system:true/false
const cats  = await DB.getTagOptions('cosplays', 'category');    // только категории
const tags  = await DB.getTagOptions('cosplays', 'tag');         // только теги
const only  = await DB.getSystemTags('meals');             // только системные модуля
// создать личный тег (пишем в модуль 'shared'):
await DB.create('tags', { name: 'Стелла из Винкс', kind: 'tag', group: 'Образы', scope: ['cosplays','purchases'] }, 'shared');
await DB.update('tags', id, { name: '...' }, 'shared');
await DB.delete('tags', id, 'shared');
```
Системные теги редактировать/удалять нельзя (`system: true` в выпадашке → без кнопок правки).

## В записях модулей
Хранить ТОЛЬКО `tagIds: ['sys:cp-wig', '<id личного тега>']` (категории и теги в одном списке). Не имена, не копии.
Имя берёшь из `getTagOptions` при отображении. Свои категории модуля (например «прическа/платье»)
— это системные категории (`kind: 'category'`). Отдельной сущности «категория» нет: категория — это тег с `kind: 'category'`.

## Связи между модулями: `refs`
У записи может быть `refs: [{ module, type, id }]`, например покупка из косплея:
`{ module: 'cosplays', type: 'items', id: '...' }`. Связь храним с ОДНОЙ стороны (там, где она
создана), обратную сторону находим запросом по `refs` на клиенте. Двусторонние копии не делаем
(рассинхронизируются). Чужие записи читай/пиши через необязательный параметр `appSlug`:
`DB.getAll('items', 'cosplays')`, `DB.update(col, id, patch, 'cosplays')`.

## Роли
При входе пользователь автоматически получает роль `user` во всех модулях
(`login/app.js`, список `ALL_MODULES`). Новый модуль добавляется в этот список и в `seed.sql`.
