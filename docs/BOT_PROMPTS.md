# Готовые задания для ботов (копируй целиком в НОВЫЙ чат Claude)

Каждый бот получает: общий блок + блок своего модуля. Один модуль — один чат.
Мержить по одному: смержил → Netlify задеплоил → проверил → следующий.
Контекст проекта и роли: `docs/ARCHITECT_HANDOFF.md`.
Приоритет заказчика: рабочие проекты → покупки → рецепты (из meals) → косплеи.

## Общий блок (одинаковый для всех)

```
Ты мигрируешь один модуль проекта LifeOS (organizz) с localStorage на общий backend.
Репозиторий (публичный): https://github.com/hasubandosan/organizz.git — склонируй его.
Прочитай по порядку: README.md, docs/ARCHITECTURE.md, docs/NEW_MODULE_HANDOFF.md.
Это инструкция и границы: общие файлы (frontend/core, hub, login, projects, backend, docs)
не трогаешь. Работаешь в ветке module/<имя> от свежего origin/main.
Человек не программист (Windows, VS Code, PowerShell). Экономь токены: без длинных
вступлений и пересказов, сначала короткий план (до 10 строк), потом работа.
Сдаёшь файл патча (git format-patch от СВЕЖЕГО origin/main: сделай git fetch перед генерацией и
проверь git apply --check) + короткий отчёт по пункту «Отчёт человеку».
К патчу ВСЕГДА прикладывай готовые команды для PowerShell (Windows, папка проекта
C:\Users\y2katbat\Downloads\organizz-clone, патч в Загрузках): checkout main → pull → новая ветка
module/<имя> → git am → git log --oneline -1 (проверка) → git push -u origin module/<имя>,
затем «на GitHub: Create pull request → Merge pull request → Confirm merge».
Данные у каждого пользователя свои (backend изолирует по владельцу) — не делай общих данных.
```

## purchases
```
Твой модуль: purchases («Покупки»). Исходники: legacy-source/purchases/ (index.html — монолит,
index.txt — вероятно заметки). Новая папка: frontend/purchases/. Слаг модуля: 'purchases'.
Особый акцент: ХАБ (frontend/hub) читает покупки для виджета и счётчика — хабу нужны статусы
(например in_stock) и поля. Опиши в отчёте точную структуру записей и коллекции, чтобы
архитектор переключил хаб на DB.getAll('purchases', 'purchases'). Модуль также связан с
core/purchase-quickadd.js и core/shopping-bridge.js — выясни, как они используют данные,
и ничего в них не меняй, только опиши, что нужно поправить.
Покупки могут иметь картинки: используй DB.saveImage/getImage.
```

## cosplays

## meals (СНАЧАЛА ТОЛЬКО РЕЦЕПТЫ)
```
Твой модуль: meals («Питание»), но заказчику сейчас нужны ТОЛЬКО РЕЦЕПТЫ: хранение и просмотр
рецептов (screens/recipes.js, recipe-view.js, recipe-edit.js, collections.js), картинки рецептов
через DB.saveImage/getImage. Меню, диеты, заготовки, шаблоны, продукты, список покупок — вне
объёма; не удаляй их, но и не мигрируй, убери из навигации или оставь неактивными (предложи как).
Исходники: legacy-source/meals/ (свои router.js, app.js, db.js; PWA: sw.js, manifest.json;
LIFEOS_MENUPLAN_INTEGRATION.md). Новая папка: frontend/meals/. Слаг: 'meals'.
ПЕРВЫЙ ШАГ — только план, код не пиши: какие коллекции нужны рецептам, какие функции его db.js

Пришли план человеку и дождись ответа, потом реализация.

архитектор). Сделай на фронте: кнопку «Импорт через ИИ», поле для текста, функцию, которая

ждёт твой код (поля рецепта), чтобы архитектор сделал под него backend.
```
